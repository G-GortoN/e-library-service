# 实施计划

[English](implementation-plan.md) | 简体中文

公开交付证据：双语应用源码的 [CI 运行 44436983590](https://github.com/G-GortoN/e-library-service/actions/runs/44436983590) 已通过 16 项后端测试、七项前端测试、类型检查与构建、Compose/Caddy 检查、镜像发布及实际容器冒烟。下方功能范围与验收标准保持完整；目标部署还需分别验证公网入口和应用邮件。部署地址、凭据、网络拓扑及运维日志仅在私有配置与记录中维护。

## 拟采用的可配置默认规则

以下为演示项目的产品假设，不是外部规定的借阅或收费政策。

| 规则 | 初始默认值 |
| --- | --- |
| 并发借阅授权 | 每本书一个 |
| 借期 | 14 天 |
| 有效借阅上限 | 每位读者五本 |
| 续借 | 最多一次，从现有到期时间起延长七天 |
| 预约顺序 | FIFO，按创建时间与 ID 排序 |
| 领取窗口 | 进入 READY 状态并创建站内通知后 48 小时 |
| 演示逾期金额 | 每逾期满 24 小时计 10 个最小货币单位 |
| 单笔借阅金额上限 | 1,000 个最小货币单位 |
| 通知时机 | 到期前一天、首次逾期，以及预约可领取、过期、取消事件 |

所有时间均存储为时间点，并按界面所选时区显示。逾期借阅不会自动归还。归还会释放授权，并冻结计算出的逾期金额。范围内不包含支付处理服务或真实扣款。

## 领域与生命周期

采用模块化单体，按书目、身份、借阅、预约、通知和演示记账组织业务。API 契约使用 DTO，服务层明确事务边界。

核心模型包括 Book、User、Loan、Reservation、Notification/Delivery、AccountToken、Fine/Adjustment 和 AuditLog。分类数据用于书目筛选与推荐。

- 书籍的上架状态与授权是否可用相互独立：DRAFT、PUBLISHED、UNPUBLISHED、ARCHIVED。
- 下架后禁止新的借阅、续借和预约，取消未完成预约并生成通知，同时保留既有借阅、归还和历史记录。重新上架不会恢复已取消的预约。
- 被禁用的用户不能继续使用已有会话或发起新的借阅相关操作。其有效预约会被取消，队列继续推进。管理员可以代为归还已有借阅，并留下审计记录。
- 管理员调整账号和角色时，不得移除最后一个已启用的管理员。
- 推荐采用分类偏好、借阅热度和近期上架书目，排除未上架书籍及读者当前借阅的书籍，并为无历史用户提供合理的默认结果。

## 并发与一致性

数据库必须确保每本书最多只有一个有效借阅。仅依靠有效借阅的唯一约束，无法保障预约优先权或每位读者的有效借阅上限。

借阅、归还、预约分配与过期、续借和下架操作必须使用经过审查的事务边界及一致的加锁策略。READY 状态的预约为其所属读者保留授权，直接借阅不能绕过队列。通过额外的唯一性规则防止重复的有效预约。

归还操作具备幂等性，并保留首次归还时间。并发重复续借不得多次延长到期时间或增加次数。通知的创建与投递必须能够恢复并去重；已回滚的操作不能向外发送成功通知。

## 身份、后台管理与邮件

角色为 READER 和 ADMIN。前端导航仅负责展示，所有敏感操作都必须经过后端授权。读者资源的归属通过当前认证身份确定，不使用客户端传入的用户 ID。

注册、验证、密码恢复和修改密码均需要输入校验与速率限制。密码恢复请求返回统一响应；恢复令牌仅保存哈希值，具有时效且只能使用一次。重置密码后旧会话失效。管理员写入凭据在部署时注入，不作为演示凭据公开。

书籍管理包括元数据与分类编辑、上下架状态转换、受限制的封面图片上传，以及可定位逐行错误的 CSV 导入预览。封面文件存放在专用的持久化媒体目录。书籍或账号停用时，不删除已有历史记录。

站内通知为必做功能。SMTP 用于验证、密码恢复和借阅通知。开发环境可以使用邮件捕获服务进行本地测试；生产邮件流程需要真实配置并验证投递。待投递状态与重试信息保存在 PostgreSQL 中，在本项目规模下不需要额外的消息中间件。

演示逾期账单使用定点数或最小货币单位计算，并展示计算依据。管理员减免和演示结清均记录审计信息，不代表真实付款。

## 前端方向

读者端采用暖白底色、深绿色主色、少量陶土色点缀、书籍封面网格、充分留白，以及易读的中英文排版。管理端共享主题，使用清晰的导航、状态标签、表格和编辑抽屉。

读者端路由覆盖书目、详情、个人书架、预约、借阅历史、账号流程、通知和演示账单。管理端路由覆盖概览指标、书籍与导入及上下架管理、用户与角色、借阅与预约、账单和审计历史。

使用共享设计变量和组件、按路由加载、可见的键盘焦点、带标签的表单和响应式布局。检查长标题、缺失封面、空数据、提交反馈和错误状态。视觉验收需要核对实际页面，安装组件库本身不能证明界面已经完成。

完整读者端和管理后台均支持中英文切换，覆盖表单、校验、错误、确认框、日期与金额。浏览器保存语言偏好，馆藏内容保留原文。本地真实 API 浏览器检查覆盖双语与语言偏好保存；本地真实 API 已通过英文馆藏 320/390/768/1440 px、全部七个管理路由、390 px 管理表格/表单、语言切换与已有校验错误、登录后读者借还检查，无横向溢出或页面脚本错误。

## 公网部署

运行目标为三个应用服务：Caddy 与静态前端、Spring Boot API、PostgreSQL。媒体、数据库和证书数据均持久化。构建和测试在开发机或 CI 上执行，不在 NAS 上运行。

主入口使用支持 IPv6 的 DDNS 主机名和 NAS 的可路由 IPv6 地址。验证分配地址、入站可达性、IPv6 防火墙策略、监听配置、地址变化、DDNS 更新和 ACME 证书签发。不公开数据库、Docker API 或 NAS 管理界面。

Funnel 作为公开备用入口，指向同一个 Web 服务。验收后在私有部署交接中提供两个链接；仅支持 IPv4 的访问者需要使用备用入口。每个主机名分别使用仅限该主机的安全 Cookie。验证与密码恢复链接必须使用配置中可信的公网基准 URL，不能直接采用未经校验的 Host 请求头。

成功的 [CI 运行](https://github.com/G-GortoN/e-library-service/actions/runs/44436983590) 已验证后端、前端和 Compose/Caddy 配置，向 GHCR 发布 API/Web 两个 `linux/amd64` 镜像，并通过 `container-smoke`。该任务验证了 Web/API/PostgreSQL 容器健康、Web/API 使用 UID 10001、持久化卷可写、应用文件系统只读、SPA/深层页面/构建后 JavaScript 资源，以及通过 Web 代理的登录/CSRF/权限/上架/借阅/归还/历史流程。两个已发布包的匿名 manifest 读取均返回 HTTP 200。仅供测试的 `APP_COOKIE_SECURE=false` 覆盖用于临时回环 HTTP，生产 Secure Cookie 默认值保持不变。

## 里程碑

1. 建立可执行的前后端骨架，锁定兼容依赖版本，并加入本地数据库迁移。
2. 完成浏览、详情、借阅、归还、当前借阅的核心流程及数据库并发测试。
3. 加入账号生命周期、后端角色权限、书籍上下架与导入及上传、账号管理。
4. 加入借期、预约、续借、通知、演示账单和推荐。
5. 完成读者端和管理端页面，通过真实交互核对视觉和可访问性状态。
6. 加入可运行的 CI、带版本的镜像、Compose、持久化、备份与恢复及重启验证。
7. 检查目标 NAS，配置 IPv6、DDNS、HTTPS 主入口和 Funnel 备用入口。
8. 完成公网端到端验收，发布准确的运维手册与发布说明；单独验证应用 JavaMail 注册/找回/借阅邮件端到端流程。

## 验证标准

- 两位用户竞争一个授权时，恰好产生一个有效借阅；不能绕过预约队列。
- 重复借阅、归还、续借和后台任务执行后，状态与金额仍符合约定。
- 其他读者的借阅、通知、预约和账单保持私密。
- 下架与禁用账号保留历史，管理员可以通过带审计的操作处理已有借阅。
- 预约过期时正确推进队列；通知失败或服务重启不丢失状态，也不重复产生事件。
- 邮件令牌会过期且不能重放；真实密码恢复邮件通过配置的 SMTP 到达收件人。
- 导入行与上传文件均经过校验，持久化文件在服务替换后仍然保留。
- 按文档搭建的全新环境能够构建和运行应用，保留的数据卷能在容器替换后保存业务数据。
- 真实外网 IPv6 网络能够访问主入口，仅支持 IPv4 的网络能够访问备用入口。
- 读者与管理员流程、视觉状态、API 文档和权限行为与发布说明一致。
